# RD-229 — Private portal implementation (staging; not deployed)

## Actual contents
- `portal-app/`: static SPA using Cognito-hosted sign-in with OAuth2 authorization code + PKCE, random one-time state, 5-minute pending-auth expiry, in-memory access token, no refresh token storage. Dashboard is hidden until `/session` returns authorized.
- `template.yaml`: AWS SAM template for **invitation-only** Cognito Lite user pool (TOTP MFA required), public browser client without a secret, regional classic hosted login domain, JWT-scoped API Gateway HTTP API, and Lambda `/session` with an exact subject allowlist. No databases, S3 private documents, or connection to PK-OS.
- `backend/index.js`: fail-closed double-check of API Gateway-supplied access token claims and exact authorized subject. Unconfigured `AllowedSubject` denies everyone.
- `tests/`: local deterministic logic checks; **not** proof that AWS configuration or end-to-end sign-in works.

## Security and deployment boundaries
This is separate from `portal-preview/` and the live root `index.html`/`CNAME`. **Do not merge the draft PR or point `srco` at this application.** The source repository is public, and static assets are still publicly retrievable even after sign-in is implemented. No credentials, token values, private research or PK-OS files may be committed. Disabling self-registration is not sufficient: the backend also requires the exact Cognito `sub`. Tokens must be validated by API Gateway JWT authorizer (issuer, audience, signature, expiry, `openid` scope) and are not trusted from client-side decoding. No real document endpoints exist yet.

Browser session deliberately does not persist tokens across refreshes; users sign in again. The Cognito logout endpoint clears the managed-login browser session, but JWTs that were already issued can remain valid until expiration; 1-hour token validity is configured. Explicit revocation/shorter session policy is a future decision. The HTML CSP is a defense in depth for **us-east-1 AWS default domains**; before production, set CSP and frame restrictions in actual Amplify HTTP response headers and recheck any custom auth/API domain. Never rely on `noindex` for privacy.

## Deployment gates — require owner approval and actual AWS access
1. Obtain a new, separate staging Amplify hostname for `portal-app/` (build output `portal-app/`, static site, not the existing root site) **without changing any live DNS**; review costs first. Set `PortalOrigin` to the exact HTTPS origin (no trailing slash).
2. Review `template.yaml`, current AWS service pricing, credit eligibility and spend alerts. Obtain explicit approval to create Cognito, Lambda, API Gateway, log group/hosting resources. Run `npm test` and `sam validate --lint` / `sam build` in an authorized environment before any deployment. Use the intended region **us-east-1**. Template itself does not deploy anything.
3. With approval, deploy the stack using the exact staging origin and unique Cognito `DomainPrefix`. `AllowedSubject` defaults empty, so the API initially denies all. Confirm Cognito self-signup off, MFA required, OAuth **code only**, public client has no secret, precise allowed callback and logout URLs.
4. Privately invite an account through Cognito, complete first-login password change and TOTP MFA. Fetch its `sub` through authenticated AWS administration; don't put it in this public repository. Update stack's `AllowedSubject` through a protected deployment parameter. Set `portal-app/config.js` to the stack's public outputs, but only in an approved deployment path; the committed public config stays intentionally blank.
5. Test anonymous API request -> 401, invalid token -> 401, unallowlisted valid user -> 403, correct MFA-authenticated subject -> 200 placeholder data, ID token -> denied, expired token -> denied, browser callback state mismatch -> denied, logout -> dashboard hidden. Inspect actual AWS charges and credits, then consider domain transfer and repository privacy separately.

**Costs:** Cognito Lite has a 10,000 MAU free allowance for direct sign-in, but email/SMS may be charged separately; this template configures TOTP, not SMS. Amplify build minutes, CDN storage/transfer, HTTP API requests, Lambda requests/compute, and CloudWatch logging can bill separately. Verify actual rates and credit applicability for this account **before deployment**. Account-wide budgets are alerts, not caps. Nothing here guarantees $0 out-of-pocket.
