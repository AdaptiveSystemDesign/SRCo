## Source and deployed components

- Branch: `feature/rd229-portal-ui-prototype`; draft PR #2 targets `main` and must stay unmerged until separate release review.
- `portal-app/`: public static frontend deployed as separate Amplify app `srco-portal-staging` at `https://feature-rd229-portal-ui-prototype.d33c5kcljm6hhd.amplifyapp.com/`, build output `portal-app`. OAuth authorization code + PKCE, one-use state, five-minute pending-auth expiry; access token held in memory and not persisted. Dashboard appears only after the protected `/session` API confirms authorization.
- `portal-app/config.js` contains only public Cognito client, Cognito hosted-login, API, and callback identifiers. It was populated on the feature branch (commit `79652078a19f692abea59f01d24f554170b3b1bb`). No credentials, private research, or token values belong in the public repository.
- `template.yaml` is the SAM source for stack `srco-rd229-staging` in `us-east-1`: Cognito Lite invitation-only pool requiring TOTP MFA, code-only browser client without a secret, scoped API Gateway HTTP API JWT authorizer, Lambda `/session`, and single Cognito `sub` allowlist. The stack was deployed, then updated with the owner's allowed subject. The code does not expose document endpoints, databases, or PK-OS connectivity.
- `backend/index.js` rechecks authorization context, issuer, client, token use, scope, and exact subject. Empty allowlist denies all. Successful response returns only two `not_connected` placeholders with `privateDataConnected: false`.

API Gateway's configured JWT authorizer is intended to enforce cryptographic signature and expiration before invoking Lambda; mock tests are not a substitute for a live ID-token or expired-token challenge.

**Outstanding live authorization tests:** a genuine other-user access token must fail with 403 after gateway validation; a genuine ID token must be refused by the protected route; and a genuinely expired access token must be refused. Establish a controlled safe test plan and obtain separate approval for any new account/resources or handling of real bearer tokens.
